# Code Intelligence 다중언어 PRD — v1.1 재검토본

기준일 2026-10-05. 기존의 낯선 레포 이해 목표를 유지하면서 학습 관리 중심 경로를 제거한다. 현재 실행 순서는 [구현 단계 A–G](11-first-implementation.md)를 따른다. 이전 평가·실패·성공 기록은 당시 증거이며 이번 변경의 완료 근거가 아니다. 맥 앱 제품 완성, 정식 배포, 수익화 검토는 별도 판정한다.

## 1. 목표와 사용자

설치 후 개발 도구를 별도 설치하지 않고, 로컬 폴더 또는 GitHub 저장소를 가져와 **어떤 코드가 어떤 구조와 관계를 이루는지 근거를 따라 이해**하는 개인용 데스크톱 도구다. 개요와 검색 가능한 분석 결과 표에서 시작해 선택한 코드 주변 관계와 해당 분석 시점의 소스를 탐색하고 변경의 영향을 검토하되, 분석되지 않은 영역과 추정을 사용자가 알아볼 수 있어야 한다.

주 사용자는 낯선 서비스에 투입된 개발자, 여러 언어의 개인 프로젝트를 이해하려는 개발자, 코드 리뷰 전에 영향 범위를 확인하는 유지보수자다. 1차 사용성 시험은 입문·중급·시니어 각 2명 이상, Java/웹/Python 경험을 섞은 총 8명으로 진행한다. 이것은 시장 수요 검증 완료 주장이 아니다.

핵심 작업은 (a) 설치→로컬 가져오기→첫 구조 이해, (b) 기능 진입점에서 데이터까지 근거 추적, (c) 심볼 변경의 확인된 의존성과 불확실한 영향을 분리하기다. AI 없이 세 작업이 완료되어야 한다. 언어가 많다는 홍보보다 실제 가능한 분석 깊이를 구매/설치 전에 알 수 있게 한다.

### 세 가지 핵심 질문

1. 이 레포의 주요 구성과 실행·요청 진입점은 무엇인가?
2. 특정 기능은 어떤 파일과 호출 경로에 구현돼 있는가?
3. 특정 파일·함수를 변경할 때 함께 확인해야 할 곳은 어디인가?

그래프·표는 답을 전달하는 수단이다. README 선언, 코드에서 확인한 사실, AI 추론을 구분하고 실행 명령을 발견한 것을 실행 성공으로 표시하지 않는다. 분석 대상의 설치·빌드·스크립트는 실행하지 않는다.

### 제거·재사용·보류

학습 진도·성장 보고·학습 과제/목표·학습 기록 작성과 관련 전용 API/서비스/질문/번역/테스트를 제거한다. notes/tasks/review/playground는 실제 용도를 확인하여 분석 메모·근거·검토 기능만 보존한다. 기존 기록과 원본 DB는 삭제하지 않으며 과거 migration은 수정하지 않는다. 파괴적 스키마 정리는 별도 승인 대상이다.

로컬 폴더 미리 보기·승인, 소스 보관·암호화, 그래프·기능·흐름·소스 탐색, 분석 이력·메모, AI 전송 미리 보기·승인·비용 원장, 앱 서비스 인증·생명주기, 백업·복원·복구 체크포인트를 재사용한다.

이번 범위는 Apple Silicon 맥에서 개요→검색/기능→선택 주변 관계→근거 소스, 정직한 분석 상태, 재분석과 격리 .app 검증이다. 마인드맵은 기존 탐색 대비 효용 검증 후 판단한다. 전체 레포 그래프 장식, 범용 AI 비서, 자동 코드 수정, 새 모델 구독 연결, 결제·멀티테넌트 API, Windows 구현/검증/배포는 보류한다. 기존 Windows 코드는 무관하게 삭제하지 않는다.

## 4. 수용 가능한 사용자 결과

- U1: 네트워크 차단·개발 도구 없는 Mac에서 로컬 개요/검색/선택 주변 관계/근거을 사용할 수 있다.
- U2: 가져오기 전에 포함·제외 사유, 실제 bytes, 범위, 언어별 예상 깊이를 확인한다. 초과하면 범위를 줄일 수 있다.
- U3: 주문 화면에서 HTTP 호출, Spring 또는 Nest handler, service, entity/table 후보까지 각 edge의 양쪽 근거를 따라간다. 끊어진 구간은 빈칸 대신 이유를 보인다.
- U4: 변경한 심볼에 대해 확인된 정적 역방향 의존, 후보 영향, 분석 밖 영역을 각각 본다. “영향 없음”은 전체 정확성 선언이 아니다.
- U5: 분석 취소·프로세스 종료·업데이트 실패 후 마지막 완성 snapshot과 노트/task를 다시 연다.
- U6: GitHub를 연결하지 않거나 연결 해제해도 로컬 기능이 유지된다. AI 키 없이 모든 핵심 기능을 사용한다.

사용성 게이트: 8명 중 7명 이상이 U1–U4 과제를 도움 없이 완료, 중대한 “추정을 확정으로 이해” 오류 0명, 심각한 데이터/권한 오류 0건. 과제 제한시간은 첫 분석 제외 15분, 화면→근거 찾기 중앙값 60초 이하. 실패 시 원인과 UI 수정 후 새로운 과제로 재시험한다.

## 6. 부모/사용자 운영 입력

**O1 단일 결정 질문(부모에 이미 보고):** GitHub App을 개인 계정과 조직 중 어디에서 소유할 것인가? 추천은 장기 유지 가능한 제품 조직 소유, device flow ON, Contents read-only/Metadata 및 선택 repository 설치다. 개인 소유로 시작해도 프로토콜과 권한은 같으며 App ID/client ID만 운영 설정이다. 실제 등록·계정 생성·허용 권한 설정은 별도 명시 승인 후 수행한다. 입력 전 G-OAUTH는 BLOCKED, 로컬 핵심 개발은 진행 가능하다.

O2 Developer ID/공증 권한 및 HTTPS 배포 도메인의 운영 주체·제공 시점은 배포 전 입력이다. 서명키를 코드/문서/일반 채팅에 넣지 않는다. 서명된 로컬 fixture와 mock updater까지 먼저 구현할 수 있으나 G-NATIVE/G-UPDATE를 대체하지 못한다.

나머지 제품 기본값(D01–D12)은 이번 기획에서 선택했으므로 불필요한 사용자 질문으로 넘기지 않는다. 운영 입력이 안전 경계를 바꾸는 대안을 요구하면 기획 재검토하며 자동으로 OAuth broker/유료 SaaS/범용 원격 endpoint를 도입하지 않는다.
