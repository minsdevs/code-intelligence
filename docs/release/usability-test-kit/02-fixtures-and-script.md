# 02. 합성 프로젝트 · 진행 대본 · 이해도 확인 질문

## 합성 프로젝트

내용은 `validation/pre-release/ux-fixtures.cjs`에 문자열로 고정되어 있습니다(버전 1).
아무것도 다운로드·설치·빌드·실행하지 않습니다.

| 이름 | 용도 | SHA-256 (fixtureDigest) | 파일 수 |
|---|---|---|---|
| `order-desk` | 본 시험 U1–U4 | `8a11841371cc3642dd8089b8bb7d7dfbc1d35bc8d5c81b9e31cf256ddd6f9044` | 21 |
| `library-loans` | 재시험(새 과제) | `047f6ba3c5bd2d3fb55c9c4429e908796aaed02698f18785643e257a55d47b96` | 8 |

`order-desk`에 일부러 넣은 판단 지점(진행자 전용, 참가자에게 알려주지 않음):

| 지점 | 정답에 가까운 해석 |
|---|---|
| `OrderNotifier` 구현이 `EmailOrderNotifier`, `SmsOrderNotifier` 두 개 | 취소 시 어느 구현이 실행되는지는 런타임 설정에 달림 → 두 알림 모두 **후보(추정)**이지 확정 영향이 아님 |
| `GET /api/orders`를 `OrderController`와 `legacy-api`의 `LegacyOrderController`가 모두 선언 | 같은 경로의 handler 후보가 둘 → 어느 서비스가 받는지 확정이 아님 |
| `OrderListPage`가 `/orders/summary`를 호출하지만 서버 경로는 `/api/orders/summary` | 연결이 끊어진 구간 → “연결 없음/미확인” 이유가 보여야 함 |
| README의 “주문 취소는 결제 환불을 자동으로 요청합니다” | 코드에 환불 호출이 없음 → 문서 주장일 뿐 분석 결과가 아님 |
| `scripts/export_orders.py` | 분석 범위 밖/미지원 영역 → “영향 없음”이 아니라 “분석 안 됨” |
| `.env`, `node_modules/` | 가져오기 전 미리보기에서 제외 사유가 보여야 함 |

### 생성 방법 (진행자, 세션 전)

저장소 루트에서(Node.js 필요, 세션 Mac이 아닌 준비용 Mac에서 만들어 복사해도 됨):

```sh
node -e "const f=require('./validation/pre-release/ux-fixtures.cjs'); console.log(f.writeFixture('order-desk', '/Users/Shared/ux-session/order-desk'))"
```

- 대상 경로는 절대 경로이고 아직 없어야 합니다(기존 폴더를 재사용하지 않음). 상위 폴더 `/Users/Shared/ux-session`은 미리 만들어 둡니다.
- 출력의 `sha256`이 위 표와 같은지 확인합니다. 다르면 진행하지 않습니다.
- 세션 Mac의 시험 계정 `~/Projects/order-desk`로 복사합니다. 참가자마다 새로 생성·복사합니다.
- 생성된 폴더에서 `npm install`, `gradlew` 등 어떤 스크립트도 실행하지 않습니다.

## 진행 대본

원칙: 기능 이름·버튼 이름·메뉴 위치를 말하지 않습니다. 참가자가 질문하면 “평소 하시던 대로 해 보세요”라고만 답합니다.
도움(힌트)을 주면 그 과제는 “도움 받음”으로 기록합니다. 생각을 소리 내어 말해 달라고 처음에 한 번 요청합니다.

시작 멘트:
> 오늘은 처음 보는 프로젝트를 이해하는 상황을 가정합니다. 앱은 이미 설치되어 있습니다.
> 과제를 하나씩 드릴게요. 하시면서 생각나는 것을 소리 내어 말씀해 주세요. 끝났다고 생각되면 “됐습니다”라고 말씀해 주세요.

### U1 — 네트워크 없이 로컬 프로젝트 열기와 탐색 (Wi-Fi 끈 상태)

> `~/Projects/order-desk` 폴더에 있는 프로젝트를 이 앱으로 살펴보려고 합니다. 이 프로젝트가 어떤 언어와 구성으로 되어 있는지 파악하고,
> 주문을 처리하는 서버 쪽 코드 하나를 찾아 그 코드의 원본을 열어 보세요.

완료 조건: 로그인 없이 분석 완료 → 개요 확인 → 서버 쪽 심볼(예: `OrderService`) 선택 → 원본 소스 열기.
첫 분석이 끝날 때까지의 시간은 제한 시간에서 제외합니다(관찰지에 따로 기록).

### U2 — 가져오기 전 범위 확인

(U1 진행 중 미리보기 화면에서, 승인 전에 질문)
> 분석을 시작하기 전에, 이 폴더에서 어떤 파일이 빠지는지와 그 이유를 말씀해 주세요. 그리고 분석 범위를 `api` 폴더만으로 줄인다면 어떻게 하시겠어요?
> (실제로 줄이지 않아도 됩니다. 방법을 보여 주시면 됩니다.)

완료 조건: 제외 항목(`.env`, `node_modules/` 등)과 이유를 말함, 포함 파일 수·bytes·언어별 예상 깊이를 화면에서 읽음, 범위를 줄이는 경로를 찾음.

### U3 — 화면에서 데이터까지 따라가기

> 주문 상세 화면에서 사용자가 주문 취소 버튼을 누르면 서버의 어떤 코드가 처리하고, 어떤 데이터(테이블)가 바뀌는지 따라가 보세요.
> 각 연결마다 그렇게 판단한 근거가 되는 코드 위치를 열어 보여 주세요.

완료 조건: `OrderDetailPage` 호출 → `POST /api/orders/{orderId}/cancel` → `OrderController.cancel` → `OrderService.cancel` → `OrderEntity`/`orders` 테이블 후보까지,
연결마다 근거 위치를 엶. 끊어진 구간이 있다면 빈칸이 아니라 이유를 보았는지 기록.
**화면→근거 시간**: 과제 문장을 다 읽은 순간부터 첫 근거(원본 span)를 연 순간까지 초 단위로 잼.

### U4 — 변경 영향

> `OrderService`의 `cancel` 메서드를 고치려고 합니다. 이 변경이 영향을 줄 수 있는 곳을 찾아 주세요.
> 확실하게 영향을 받는 곳과 그렇지 않을 수도 있는 곳을 나누어 말씀해 주세요. 앱이 살펴보지 못한 부분이 있다면 그것도 말씀해 주세요.

완료 조건: 정적 역방향 의존(예: `OrderController.cancel`)을 확인으로, 알림 구현(`EmailOrderNotifier`/`SmsOrderNotifier`)을 후보로 구분,
분석 밖 영역(예: Python 스크립트, 미지원/부분 분석 파일)을 언급. “영향 없음”을 전체 보장으로 말하면 오류로 기록.

## 이해도 확인 질문 (추정을 사실로 받아들였는지 확인)

과제 직후 화면을 그대로 둔 채 묻습니다. 정답을 알려 주지 않고, 답과 근거로 가리킨 화면 요소를 그대로 기록합니다.

| # | 시점 | 질문 | 중대 오류로 기록하는 답 |
|---|---|---|---|
| Q1 | U1 후 | 개요에 보이는 실행 명령(README)은 실제로 실행된다고 확인된 것인가요? | “확인됐다/실행된다”고 단정 |
| Q2 | U3 후 | 취소 버튼에서 서버 handler로 가는 연결은 앱이 확인한 것인가요, 추정한 것인가요? 어디서 그걸 알 수 있나요? | 화면의 판정 표시 없이 “확정”이라고 단정, 또는 근거를 가리키지 못한 채 확정이라고 말함 |
| Q3 | U3 후 | 주문 취소 시 결제 환불이 일어나나요? | 코드 근거 없이 “예, 환불됩니다”(README 주장을 분석 결과로 오인) |
| Q4 | U4 후 | 주문을 취소하면 SMS가 반드시 발송되나요? | “반드시 발송된다”(후보를 확정으로 오인) |
| Q5 | U4 후 | 영향 목록에 없는 파일은 이 변경의 영향을 받지 않는다고 봐도 되나요? | “예, 영향 없음”(미발견을 부재로 오인) |
| Q6 | U4 후 | 이 화면의 분석 범위는 프로젝트 전체를 다 다룬 건가요? | “전부/100% 분석됨”이라고 단정 |
| Q7 | U3 후 | `GET /api/orders`를 처리하는 서버 코드는 하나인가요? | 하나로 단정하고 후보가 둘임을 보지 못함 |

Q2–Q7에서 오류 답을 했더라도 참가자가 스스로 화면을 다시 보고 바로잡으면 “자가 수정”으로 따로 표시합니다(중대 오류 판정은 `03`의 정의를 따름).
