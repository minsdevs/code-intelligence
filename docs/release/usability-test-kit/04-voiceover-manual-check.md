# 04. VoiceOver 수동 점검표 (약 30분)

자동 측정(`validation/pre-release/ux-accessibility-pilot.cjs`)은 Chromium 접근성 트리와 키보드 이동을 봅니다.
실제 VoiceOver 낭독은 사람이 들어야 하므로 이 표로 확인합니다. 결과는 PASS / FAIL / 해당 없음과 실제로 들린 문장을 적습니다.

준비(5분): 시험 전용 macOS 계정, 후보 빌드, `order-desk` 분석 완료 상태, AI OFF, GitHub 미로그인.
VoiceOver 켜기 `⌘F5`, VO 키 = `Control+Option`. 화면 크기 1280×800, 시스템 언어 한국어로 1회(영어는 시간이 남으면 반복).

| # | 화면 | 동작 | 기대 결과 | 결과 | 들린 문장 |
|---|---|---|---|---|---|
| V1 | 홈 | `VO+U` → 랜드마크 | 주 내비게이션과 본문(main)이 이름과 함께 나열됨 | | |
| V2 | 홈 | `VO+U` → 제목 | 페이지 제목(h1)이 있고 수준이 건너뛰지 않음 | | |
| V3 | 가져오기 | 로컬 폴더 선택 → 미리보기 | 포함/제외 파일 수, bytes, 제외 사유가 표·목록으로 읽힘(색만으로 구분하지 않음) | | |
| V4 | 분석 진행 | 분석 시작 후 아무 키도 누르지 않고 기다림 | “분석 단계 n/m: … 진행 중” 같은 진행 안내가 자동으로 낭독됨(초점 이동 없이) | | |

| V11 | 코드 | 소스 보기에서 호출자 목록 | 추정 호출자에 “추정 (LIKELY)” 등 글자 표시가 읽힘, 빈 목록은 “관계가 없다는 증거는 아닙니다”로 읽힘 | | |
| V12 | 흐름(Flows) | 흐름 선택 | 정적 경로라는 안내와 단계 목록이 순서대로 읽힘 | | |

판정 규칙: V4·V7·V8·V11·V13 중 하나라도 FAIL이면 화면 낭독기 사용자의 U1–U4 수행이 막히거나 추정이 확정으로 들리므로 High로 기록합니다.
나머지 FAIL은 Medium으로 기록하고 재현 방법(화면, 동작, 들린 문장)을 함께 남깁니다.
