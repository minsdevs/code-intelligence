## 수정

`TsAnalyzerException`, `TreeAnalyzerException`이 기존 `RecoveryActionFailure` 계약을 구현한다. 기존 `JobWorker → JobRepository.markJobFailed → analysis_jobs.failure_code → JobDetailResponse` 경로를 그대로 사용한다. JobWorker, DB 스키마, 재시도 정책은 변경하지 않았다.

| 관측 | 저장 코드 |
| --- | --- |
| typed HTTP/socket timeout 또는 control watchdog 만료 | `TS_ANALYZER_TIMEOUT` / `TREE_ANALYZER_TIMEOUT` |
| 연결 단절·접속 실패 등 비입력 transport 실패 | `TS_ANALYZER_TRANSPORT_ERROR` / `TREE_ANALYZER_TRANSPORT_ERROR` |
| HTTP 4xx 입력 거절 | `TS_ANALYZER_REJECTED` / `TREE_ANALYZER_REJECTED` |
| 기존 TS 구문·분석 한도·격리 실패 | `TS_SYNTAX_ERROR`, `ANALYSIS_LIMIT`, `ADAPTER_ISOLATION_UNAVAILABLE` 유지 |

- `AnalyzerFailureKind`는 예외 타입/HTTP 상태만 사용한다. 오류 메시지나 응답 문자열로 timeout/crash를 추정하지 않는다. 소켓 단절만으로 process crash를 확정할 수 없어 transport로 분류한다. 기존 XPC `ADAPTER_CLOSED`는 isolation 코드 유지.
- pinned TLS 원인을 제거하기 **전** timeout 분류를 계산하므로 비밀/원문 cause를 보관하지 않으면서 안정 코드를 유지한다.
- control socket은 watchdog 만료를 별도 기록한다. interrupt 처리와 요청별 timeout 값은 그대로다.
- 정상 analyzer 응답의 파일별 syntax/input 결과를 transport 오류로 바꾸지 않았다. 기존 syntax·limit·isolation override와 단일 attempt 동작을 검증했다.
