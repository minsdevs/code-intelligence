## 원인과 수정

기존 클릭·DOM 관측은 모두 renderer의 `performance.now()`였다. Node 시계는 timeout과 별도 진단에 쓰였으며 ACK 계산에 섞이지 않았다. 확인된 결함은 취소 관측 조건에 문자열을 전달하여 `"Cancelling…".includes("")`가 참이 되는 점이다. 빈 아이콘 버튼이 있으면 observer 설치 시점에 ACK가 기록되고, 실제 클릭이 뒤따라 음수가 된다. 회귀 fixture의 설치 100 ms / 클릭 121 ms는 기존 경로에서 -21 ms를 만들 수 있는 순서를 재현한다. 후보의 기존 -21..-12 ms 원시 기록은 그대로 무효이며 새 기록으로 바꾸지 않는다.

- 공통 renderer 함수 `installWorkloadClick` / `installWorkloadWatch`로 실제 클릭과 DOM 관측을 같은 단조 시계에 유지한다. 버튼은 비어 있지 않은 전체 문자열만 일치시킨다.
- preview/cancel/refresh-preview는 클릭 mark 초기화 → observer 설치 → 사용자 동작 순서로 실행하고, 클릭 mark 이전의 상태는 ACK로 인정하지 않는다. 음수를 0으로 자르지 않는다.
- smoke 평가도 유한·비음수 값을 요구한다. 과거 음수 값은 출력에 보존하면서 `withinLimit: false`로 처리한다. 기존 series 실패 규칙은 유지한다.
- `adapter-isolation-stage.cjs`의 느슨한 dialog 복제 코드를 삭제하고 기존 `withFolderPicker`를 사용한다. preview 버튼이 나타날 때까지 helper 범위에서 기다린다. title/properties/단일 호출 검증, message box 거부, 복원·dispose 규칙을 공유한다.
- main-process 응답 record는 정확한 키 및 비음수 안전 정수로 검증한다. 잘못된 record는 `FOLDER_PICKER_RESPONSE_INVALID`로 실패한다.
- 기존 export는 제거·변경하지 않았다. 새 export와 runner 소비자를 함께 갱신했다. 이 세션에는 LSP 도구와 `typescript-language-server` 실행 파일이 없어 호출점은 grep으로 확인했다.
