## Absent release key

`desktop/build/update-keys.json` ships `keys: []`, `manifestUrl: null`, `allowedHosts: []`, `teamId: null`. The parser is
all-or-nothing: with this file the updater is disabled (no menu item, no request; `check()` → `UPDATE_NOT_CONFIGURED`),
validation `--mac dir` builds are unaffected, and a distribution build (`dmg`/`zip`) stops in `beforePack` with
`UPDATE_KEYS_MISSING` before any signing step. Fixture keys exist only in test memory (`desktop/test/fixtures`).
Releasing requires the owner to add the Ed25519 public key (SPKI DER, base64) of an offline release key, the update
host and the Developer ID Team ID (O2).

## Limits and open points

- Packaged acceptance NOT RUN: no candidate was built here. The next candidate must show `build/update-keys.json`
  inside `app.asar` (electron-builder excludes `build/` unless listed; it is listed explicitly) and a normal start
  writing `update-checkpoints/schema.json` and one `BUILD_STARTED` record.
- The update-check dialogs and app menu (`update-startup.cjs` `checkForUpdates`) have no unit test and are inert
  with the shipped key file; the recovery dialog is covered by the main harness. No frontend change was needed.
  Daily automatic checks are not implemented (user-initiated only).
- The checkpoint is a cold physical copy, not the logical encrypted backup archive: the backup export policy only
  reads a database at the bundled schema, so it cannot export the previous schema before migration. On APFS the
  clone shares blocks; one finished checkpoint is retained and diverges up to the database size over time.
- A start that fails or is quit before the backend is healthy leaves the checkpoint open, so the next start is
  recovery-only (with "Try the upgrade again"); a transient failure therefore costs one dialog.
- The deterministic checkpoint ID lets a publisher bind a recovery manifest to "data of build N upgraded by build M"
  without per-installation knowledge; this changes no reference test but is a contract decision to review.
- `ai-egress-boundary.test.cjs` now allows one reviewed Electron `net` path (G-COST/G-SEC reviewers should confirm).
- C14 U1–U10 (plan §5) remain BLOCKED on O2 inputs (Developer ID, notary profile, update host/TLS, offline release key, clean Mac).
