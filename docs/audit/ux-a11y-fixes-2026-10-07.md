## What changed

**A10 — contrast (WCAG 2.1 AA, 4.5:1 for normal text).** Only colour values changed;
the dark palette, spacing and dividers are as before.

| Token | Before | After | Lowest ratio over surface-0…3 |
|---|---|---|---|
| `--color-ink-faint` | `#64646e` (2.40–3.09) | `#93939d` | 4.61 (surface-3) |
| `--color-ink-muted` | `#94949e` (4.67–6.01) | `#a8a8b2` | 5.95 (raised to keep muted above faint) |
| `--color-danger` | `#e06c75` (4.39 on surface-3) | `#e57d86` | 5.09; 4.73 on `bg-danger/5` |

`CoveragePanel` uses tokens instead of Tailwind gray/amber/red (the `#6a7282` and
`#4a5565` pairs). Monaco uses a new theme `code-intelligence-dark`
(`frontend/src/lib/monacoTheme.ts`): the vs-dark rules with the seven token colours
under 4.5:1 on `#1E1E1E` raised (`annotation #cc6666 → #d67b7b`, comment, regexp,
`variable.predefined`, `delimiter.html/xml`, `tag.*.pug`, `string.sql`). The test
checks every token on every surface, every text/background pair written in one class
list (translucent backgrounds over each surface), forbids palette text colours outside
the tokens, and checks every Monaco rule.

**A18 — document language.** `I18nProvider` sets `document.documentElement.lang` from
the UI language. All 308 hard-coded Hangul lines (overview, neighbourhood, coverage
report, local import preview/status, installations, code viewer, judgement editor,
settings, sidebar, features, flows, analysis, playground, review, notes, progress,
import wizard) moved to `translations.ts` with English text; Korean text is
unchanged, so Korean-mode tests are unaffected. The only Hangul left in product code is
the `한국어` language option, now rendered with `lang="ko"`.

**A12 — focus placement.** After a folder is chosen, focus moves to the
“Confirm local import” heading. When the preview loads, focus moves to the preview
heading and a polite status says the preview is ready with the selected file count
(the status region stays mounted so the text is announced). When the analysis
finishes, the wizard opens the overview with `{ analysisFinished: true }`; the
workspace focuses its `h1` (project name) once and shows an `sr-only` status
“Analysis finished … check the analysis coverage report”. A normal overview visit
moves no focus.

**A4 — graph keyboard semantics.** Chosen: name nodes and edges and keep them
focusable, not `aria-hidden`. Reason: the architecture canvas has no table
alternative, so hiding it would remove the only keyboard path to its nodes; the
neighbourhood keeps its table (A5) as the full alternative. Changes in
`RepositoryNeighborhood` and `ArchitectureCanvas`:

- edge names `source → target · edge type · verdict` (neighbourhood) and
  `source → target · N relations` (architecture); node names `name · file`
  (selected item marked), `name · type · file`, `LAYER layer`; no database ids;
- Enter on a focused node does what a click does (React Flow alone only selects it);
- React Flow's keyboard hints (“Press delete to remove it”) replaced by accurate,
  translated hints; `deleteKeyCode={null}`;
- `index.css`: `.react-flow .react-flow__edge:focus-visible` and
  `.react-flow .react-flow__node:focus-visible` get a 2 px accent outline; a focused
  edge path is drawn in the accent colour at 3 px (React Flow sets `outline: none`).

## P4 — preview language counts, expected depth, scope reduction (not done)

The backend preview response lacks the data, so no frontend change was made.
`LocalSourcePreview` (`backend/…/project/LocalSourcePreview.java`) carries only token,
expiry, operation, source name, base snapshot, change counts, changed paths and
`LocalImportService.ImportSummary` (accepted files, bytes read, exclusions by reason).
There is no per-language count, no analyzer/depth capability, and neither
`POST /api/projects/local/preview` (`LocalPreviewRequest(path, name)`) nor the create
call accepts a scope (include/exclude) parameter. Deriving languages from file
extensions in `changedPaths` would be a guess and still give no expected depth.
Needed (backend + UI, another unit): per-language file counts from the inspection, an
expected-depth value per language from the analyzer capability matrix, and a scope
parameter on preview and create that the approval token binds to.

## Limits and what remains

- JSDOM has no layout or rendering: focus, names and CSS rules are checked, not how
  the focus ring paints on an SVG edge in Chromium, and not VoiceOver speech (A20).
- The contrast test checks normal-text 4.5:1 for all text tokens and class-list pairs;
  inline `style` colours (graph node borders, legend swatches) are not text and are
  not checked. Disabled controls (`disabled:opacity-*`) are exempt as in WCAG.
- Hard-coded English in Korean mode (for example `Projects / Import`, `Cancel analysis`)
  is outside A18 and unchanged.
- Playwright e2e specs and the packaged pilot were not run (no new candidate).
- Remaining for G-UX: rebuild a candidate with these commits and rerun
  `ux-accessibility-pilot.cjs` (A4, A10, A12, A18 must be re-measured); P4 needs the
  backend change above; A9/A16 (Low) and P8 (Medium) are untouched.
